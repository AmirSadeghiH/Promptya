# Phase 12 — Promptya Developer Hub

## Objective

Build a useful, SEO-oriented developer resource layer without turning Promptya into an unrelated software directory.

## Positioning

The developer hub should be a coherent resource for:
- AI coding tools
- AI agents
- coding assistants
- harnesses
- MCP
- model providers
- developer infrastructure
- prompt engineering for developers
- practical guides

Potential tool pages should answer:
- what it is
- who it is for
- key capabilities
- pricing/status where verified
- strengths/limitations
- example use cases
- related tools
- useful prompts or workflows

## Required Engineering

Prefer Django server-rendered pages.

Use structured, indexable URLs and metadata.

Avoid thin pages created only for SEO.

Where external facts can change, design content so it can be updated safely.

## Hard Prohibitions

- Do not add hundreds of autogenerated thin pages.
- Do not fabricate pricing, benchmarks, or capabilities.
- Do not scrape content without permission.
- Do not introduce a frontend framework solely for the hub.
- Do not dilute the core Promptya product.

## Acceptance Criteria

- Developer hub has clear information architecture.
- Pages provide real user value.
- SEO metadata is meaningful.
- Content is maintainable.
- Internal linking connects the hub to relevant Promptya capabilities.

## Verification

Test routing, templates, metadata, canonical URLs, sitemap behavior, mobile layout, and page performance.

## Final Report

Include information architecture, page types, SEO strategy, and content-maintenance model.
